# Multi-Backend Support

Model-setup supports installing multiple ML backends (PyTorch, TensorFlow) and switching between them easily. This is useful for testing different Keras 3.x backends or when certain models work better with specific backends.

## What Are Backends?

In Keras 3.x, you can choose which framework executes your model:

- **torch**: PyTorch (default, recommended)
- **tensorflow**: TensorFlow
- **jax**: JAX (experimental support)

## Installing Multiple Backends

### Using `--all` Flag

```bash
python test_venv_builder.py ~/venv \
    --config ~/hardware_config.json \
    --all
```

This will:
1. Detect your GPU (e.g., CUDA)
2. Install **all working backends** for that GPU:
   - torch (CUDA)
   - tensorflow (CUDA)
3. Generate `keras_backend.py` with commented switch options
4. Create separate venv directories if needed

### Example Output

```

  Hardware: cuda
  GPU: NVIDIA GeForce RTX 4060
  Primary Keras Backend: torch

    - torch (cuda) (active)
```

## Switching Backends

### Generated keras_backend.py

```python
"""Keras backend initialization.

Auto-generated by model-setup. Do not edit manually.
Primary backend: torch
"""

import os

# Set Keras backend BEFORE importing keras
# Active backend: torch
os.environ["KERAS_BACKEND"] = "torch"

# Alternative backends (uncomment to switch):
# Backend: tensorflow (cuda)
# os.environ["KERAS_BACKEND"] = "tensorflow"

# Import keras with configured backend
import keras

__all__ = ["keras"]
```

### Manual Switch

Edit `model_core/keras_backend.py`:

```python
# Comment out torch
# os.environ["KERAS_BACKEND"] = "torch"

# Uncomment tensorflow
os.environ["KERAS_BACKEND"] = "tensorflow"
```

Then restart your Python kernel or script.

### Verify Current Backend

```python
import keras
print(keras.config.backend())  # 'torch' or 'tensorflow'
```

## Backend Compatibility

### PyTorch (torch)

**Pros:**
- ✅ Best Jetson support (NVIDIA provides official wheels)
- ✅ Dynamic compute graph
- ✅ Easier debugging
- ✅ Preferred for research

**Cons:**
- Model serialization different from TensorFlow
- Some production tools prefer TF format

### TensorFlow

**Pros:**
- ✅ Mature production ecosystem
- ✅ TensorBoard visualization
- ✅ Wide deployment options
- ✅ TFLite for mobile/edge

**Cons:**
- Installation can be complex
- Less dynamic than PyTorch
- GPU support on Jetson limited

### JAX

**Pros:**
- ✅ Fast compilation
- ✅ Functional programming style
- ✅ Good for research

**Cons:**
- ⚠️ Limited support in model-setup
- Less mature ecosystem
- Different API style

## Hardware Support Matrix

| Hardware | torch | tensorflow | Notes |
|----------|-------|------------|-------|
| Jetson | ✅ Full | ⚠️ Limited | NVIDIA doesn't provide TF wheels |
| CUDA | ✅ Full | ✅ Full | Both work well |
| ROCm | ✅ Full | ❌ Not tested | PyTorch recommended |
| CPU | ✅ Full | ✅ Full | Both work |

## When to Use Multiple Backends

### Testing Models

Some models or libraries work better with specific backends:

```python
# Test with torch
torch_model = create_model(backend='torch')

# Compare with tensorflow  
tf_model = create_model(backend='tensorflow')
```

### Production Deployment

- **Development**: Use torch (faster iteration)
- **Production**: May use TensorFlow (if deployment requires it)

### Performance Comparison

```python
import time
import keras

# Time with current backend
start = time.time()
model.fit(X, y, epochs=10)
print(f"{keras.config.backend()}: {time.time() - start}s")
```

## Storage Considerations

Installing multiple backends requires more disk space:

- **Single backend**: ~2-3 GB
- **Multiple backends**: ~4-6 GB

Backends are stored in separate venv directories when using `--all`:

```
venv-primary/      # torch (active)
venv-tensorflow/ # tensorflow (alternative)
```

## Troubleshooting

### "Backend not available"

**Cause**: Installed with one backend, trying to use another.

**Solution**: Re-install with `--all` flag:
```bash
python test_venv_builder.py ~/venv --all --config ~/config.json
```

### "ImportError: cannot import name 'torch'"

**Cause**: Switched to tensorflow backend but torch model saved.

**Solution**: Models are backend-specific. Re-train or use same backend.

### Switch not working

**Cause**: Keras already imported before switching.

**Solution**: Must set environment variable BEFORE importing keras:

```python
import os
os.environ["KERAS_BACKEND"] = "tensorflow"  # Set first!

import keras  # Import after setting
```

## Best Practices

1. **Default to torch**: It's the most reliable, especially on Jetson
2. **Test both**: If you need TF compatibility, test both backends during development
3. **Save checkpoints**: Save model weights (backend-agnostic) not full models
4. **Document backend**: Note which backend was used for each experiment

## API Reference

### Checking Available Backends

```python
from model_setup.venv_builder import create_venv_for_hardware

venv, hardware, primary_backend, all_backends = create_venv_for_hardware(
    "/path/to/venv",
    "/path/to/config.json",
    install_all=True  # Install all working backends
)

print(f"Primary: {primary_backend}")
print(f"All available: {[b[0] for b in all_backends]}")
# Output: ['torch', 'tensorflow']
```

### Hardware Config Format

```json
{
  "gpu_type": "cuda",
  "keras_backend": "torch",
  "available_backends": ["torch", "tensorflow"]
}
```
